Every plant I have worked in runs on data that has quietly stopped matching the material on the floor. Counts drift. Work in progress goes missing between the stock room and the machine. Offcuts get scrapped because no record says they exist. Damage is found weeks after it happened, in the wrong department, with no evidence left. Every decision downstream is then made against a fiction, and nobody making those decisions can tell.

Closing that gap is most of what I build. Some of it reconstructs the truth after the fact, which is the expensive way and usually the only way available. The better answer, and the direction the work has been moving, is to capture each event where and when it physically happens so there is nothing left to reconcile.

Three and a half years as a manufacturing engineer designing assembly lines and running time studies, then into procurement. Both jobs ran on spreadsheets that broke quietly and ERP screens nobody could get data out of. I started writing the tools myself, and that is now most of what I do.

Most of it runs inside a plant. Where a number appears below, I say how it was measured. Where something was not measured, I say that instead.

Inventory Database

A small manufacturer's entire material flow, running inside one Excel workbook. Free, and the code is public.

Office Scripts (TypeScript) · Excel on the web · browser preview

Open the browser preview No install, no signup. Works on a phone.

What the preview is, and what it is not. It runs the real workflow and the real reorder logic, but entirely in browser memory. Refresh it and everything resets. It exists so you can see the thing work in ten seconds, not so you can run a plant on it. The working version is the Office Scripts, and you install those into a workbook yourself: import the sample workbook, add six scripts from Excel's Automate tab, attach a button to each. The setup steps are here. Worth being explicit about the seam, because it is the part people assume wrongly: exporting to xlsx gives you the data, not the automation. Scripts do not travel inside the file.

Raise a purchase order, email it to the supplier, receive it into stock, move it to the production floor, record what was actually consumed, ship the finished goods. Every movement timestamped.

The reorder alert is the part worth looking at. It does not check whether stock sits below a minimum. It checks whether a product will run out before an order placed today could physically arrive, measuring its recorded daily usage against that supplier's lead time, and it drops anything already on order. That is the difference between an alert people act on and one they learn to ignore.

Moving material to production and consuming it are separate actions, because they are separate events. Stock leaving the stock room is relocated, not spent. Collapsing those two is the usual shortcut and it is why work in progress goes missing.

Found in review. CreatePO numbered orders from the open-PO row count, so deleting one tidied-up closed row would reissue a number already in the log. It had never fired, because receiving closes rows rather than deleting them. Fixed. It is the same row-position-as-identity mistake I had caught in someone else's code, further down this page, and then written into my own.

Cutting stock optimizer

Extrusion profiles were cut order line by order line against 192 inch bars. No packing logic, and every offcut became scrap.

Python · first-fit-decreasing packing · SQLite · Tkinter

Bin packing across the whole order set instead of one line at a time, plus a SQLite remnant registry so an offcut created in one run is found and used by the next, plus a Tkinter app the cutters run at the saw.

Production reports turned out to be .xls, not the CSV I had been testing against, so I added native .xls reading rather than ask the floor to change how they export.

Unproven. I have no measured waste reduction. The packing is demonstrably tighter and remnants that used to be scrapped now come back, but whether that shows up in monthly scrap tonnage has not been checked against a baseline. That is the number that matters and I have not earned it yet. The floor app's logic is covered by tests; its GUI has not been run at the saw.

Cycle count validation, rebuilt

The script reconciling daily counts had been trusted for a long time. It was wrong in four ways, all of them silent.

Office Scripts (TypeScript) · Excel · OneDrive

  • A dead fraction parser read "1/2" as 1, rounding every half count up with no warning.
  • Validation ran one direction only, so shrinkage and missed pulls never surfaced.
  • Batch IDs were recomputed per row, splitting one count session in two whenever it crossed a second boundary.
  • A crash window let a re-run duplicate rows already committed.

Rebuilt around an immutable key of ID plus batch time plus type. The old version keyed on row numbers, which drift as history grows, so a correction written today could land on a row counted last month. Then split into three scripts so the job could be handed to five people across purchasing, production control and receiving, and run for two weeks without me.

Unknown. How long those four bugs had been running, and how much count drift they left in the records. All four failed silently, which is why they lasted. I did not go back and quantify the damage.

Glass defect tracking

Glass arrived damaged often enough to matter and we had no evidence to put in front of the supplier.

Streamlit, abandoned · receiving bay observation

I built a Streamlit app to log defects at the moment of detection, then abandoned it. The storage design did not scale the way I had built it, and the glass department was never going to use a second screen mid-unload.

The useful output came from standing at the receiving bay instead. Sheets are fixed longitudinally on the trucks but free laterally, so a hard turn can load them edge on and start fractures nobody sees until the glass is cut. The replacement tracker is being built from the reorder emails, which already carry photos, dates and quantities.

Caveat. That is a hypothesis, not a finding. I have a plausible mechanism and no evidence it is the cause. Testing it means correlating damage against route and load position, and that has not happened. I am not calling it a root cause until it survives that.

CNC material logging

Material pulled at the CNC was written on paper and keyed in later, or not at all.

Standalone HTML · Android tablet at the machine

The first attempt was a Power Automate flow and it failed in practice. I replaced it with a single HTML file on a tablet mounted at the machine. The operator taps the part, it logs. No install, no licence, no server.

This is the only tool here that does not reconcile anything. The others reconstruct what happened from records written later; this one records the event at the machine, at the moment of the pull, so there is no gap to close afterwards. That is the more expensive thing to build and the direction I would take the rest of this work given the chance.

Measured by. It is still in use, which is the only measurement I have. For a floor tool that is not nothing, since anything the operators dislike gets quietly abandoned inside a week. Whether the logged data is accurate enough to reorder from is a separate question I have not answered.

Outside work

Pet TV Factory

Hour long ambient video for pets left home alone. The interesting constraint is encode cost.

Python · ffmpeg · GitHub Actions · pytest

Encoding an hour of 1080p is expensive, so it builds one unique ten minute block with crossfades and repeats it to full length losslessly through ffmpeg's concat demuxer. An hour costs the same CPU as ten minutes.

Runs weekly on GitHub Actions. A synthetic mode lets CI pass with no API key, a seed flag makes output reproducible, and music selection follows published animal behaviour work rather than guesswork, restricted to CC0 audio because Content ID will flag an hour long upload.

My Evil Diary

A horror fiction writing surface with no text box and no send button. The whole page is ruled parchment and you write onto it, so Apple Pencil works natively.

Python, standard library only · JavaScript · Web Crypto

The real problem was privacy. The passphrase is hashed in the browser and only the hash reaches the server, so there is no identity check to talk your way past and no way to recover a forgotten passphrase. Those are the same property stated in both directions, and the README says so rather than promising a recovery it cannot deliver.
