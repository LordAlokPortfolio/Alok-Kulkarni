Inventory Database

Office Scripts (TypeScript) · Excel on the web · static HTML and JS demo

Click through the live demo no install, no signup, works on a phone

A full material flow for a small manufacturer, running inside a single Excel workbook: raise a purchase order, print or email it to the supplier, receive it into stock, move it to the production floor, record what was actually consumed, ship finished goods, and log every movement with a timestamp.

The part that matters The reorder alert is not a threshold check. It flags any product that, at its recorded average daily usage, will run out before a purchase order placed today could physically arrive, measured against that supplier's lead time. Products with an order already in flight are excluded so the list stays actionable. That is the difference between an alert people act on and an alert people learn to ignore.

Also Moving material to production and consuming it are separate actions, because they are separate events. Stock leaving the stock room is relocated, not spent; it comes off the books when it is used. Collapsing those two into one is the usual shortcut and it is why work-in-progress goes missing.

Shipped as Two deliberately different implementations. The browser demo is stateless and resets on refresh, and says so on the page. The Office Scripts are the real tool and write to the workbook permanently. The demo generates a PDF in-browser; the Office Script version fills a print-ready sheet and hands off to Excel's own export, because Office Scripts cannot produce a PDF or send mail and pretending otherwise would just break for whoever tried it.

Written for Someone who rarely touches a computer. The page is a numbered walkthrough, step one through seven, in plain language.

Found in review CreatePO was numbering orders from the open-PO row count, which assumes rows are only ever appended. Delete one tidied-up closed order and the next PO is issued a number already sitting in the log. It had never fired, because receiving marks rows closed instead of deleting them, so the count only ever grew. It would have fired the first time someone cleaned up the sheet by hand. Now derived from the highest existing PO number, skipping anything that does not match the expected shape. Worth recording because the browser demo had always done this correctly with a plain counter, and because it is the same row-position-as-identity mistake described two sections below, in code I had written myself after finding it in someone else's.

Cutting stock optimizer, extrusion

Python (first-fit-decreasing packing) · SQLite · Tkinter · xlrd

Problem Extrusion profiles were cut order line by order line against 192 inch stock bars. No packing logic, no reuse of offcuts. Every remnant became scrap.

Built First-fit-decreasing bin packing over the order set, plus a SQLite remnant registry so an offcut created in one run is available to the next, plus a Tkinter app the cutters use at the saw.

Result Tested against real production orders. A two-run test confirmed a remnant created in run one was correctly found and consumed in run two. Production reports turned out to be .xls, not the CSV I had been testing against, so I added native .xls ingestion rather than ask anyone on the floor to change how they export.

Status Optimizer and remnant registry verified against production data. Floor app decision logic covered by automated tests; the GUI has not yet been run at the saw.

Unproven I do not have a measured waste reduction. The packing is demonstrably tighter per order than cutting line by line, and remnants that used to be scrapped now come back, but whether that shows up in monthly scrap tonnage has not been checked against a pre-optimizer baseline. That is the number that actually matters and I have not earned it yet.

Cycle count validation, rebuilt

Office Scripts (TypeScript) · Excel · OneDrive

Problem The script reconciling daily cycle counts had been running for a long time. It was wrong in four ways, all of them silent.

  • A dead fraction parser read "1/2" as 1. Half counts were being rounded up with no warning.
  • Validation ran in one direction only, so shrinkage and missed pulls never surfaced.
  • Batch IDs were recomputed per row, which split a single count session in two whenever it crossed a second boundary.
  • A crash window let a re-run duplicate rows that were already committed.

Built Rebuilt the reconciliation around an immutable row key (ID + BATCHTIME + TYPE). The previous version keyed on row numbers, which drift as history grows, so a correction written today could land on a row counted last month.

Result Split into three scripts (setup, validate, push) so the job could be handed to five people across purchasing, production control and receiving, and run for two weeks without me.

Unknown How long those four bugs had been running, and how much count drift they put into the records before I found them. All four failed silently, which is why they lasted. I did not go back and quantify the damage.

Glass defect tracking

Streamlit (abandoned) · receiving-bay observation

Problem Glass arrived damaged often enough to matter, and we had no evidence to put in front of the supplier's rep.

Built A Streamlit app to log defects visually at the moment of detection. I abandoned it. The storage design did not scale the way I had built it, and the glass department was not going to use a second screen during unloading.

Result The useful output came from standing at the receiving bay instead. Sheets are fixed longitudinally on the delivery trucks but free laterally, so a hard turn can load them edge on and start fractures that nobody sees until the glass is cut. The replacement tracker is being built from the reorder emails, which already carry damage photos, dates and quantities.

Caveat The transport idea is a hypothesis, not a finding. I have a plausible mechanism and no evidence it is the cause. Testing it means instrumenting a delivery, or at minimum correlating damage rates against route and load position, and neither has happened. I am not going to call it a root cause until it survives that.

CNC material consumption logging

Standalone HTML · Android tablet at the machine

Problem Material pulled at the CNC was recorded on paper and keyed in later, or not at all.

Built First attempt was a Power Automate flow. It failed in practice. I replaced it with a single HTML file on an Android tablet mounted at the machine: the operator taps the part, it logs. No install, no licence, no server.

Result It is still in use. That is the only measurement I have, and for a floor tool it is not a trivial one, since anything the operators dislike gets quietly abandoned inside a week. Whether the logged consumption is accurate enough to drive reordering is a separate question I have not answered.

Pet TV Factory

Python · ffmpeg · GitHub Actions · pytest

Generates hour-long ambient video for pets left home alone. The interesting constraint is encode cost. Encoding an hour of 1080p is expensive, so it builds one unique ten-minute block with crossfades, then repeats it to full length losslessly through ffmpeg's concat demuxer. An hour costs the same CPU as ten minutes.

Runs weekly on GitHub Actions. --synthetic mode lets CI pass with no API key, --seed makes output reproducible, and the pure logic is covered by pytest with no network or ffmpeg needed. Music selection follows published animal behaviour work (Wells 2002, Kogan 2012, Snowdon, Teie and Savage 2015) rather than guesswork, and is restricted to CC0 audio because Content ID will flag an hour-long upload.

My Evil Diary

Python (stdlib only) · JavaScript · Web Crypto

A horror fiction writing surface with no text box and no send button: the whole page is ruled parchment and you write directly onto it, which means Apple Pencil Scribble works natively on iPad.

The design problem was privacy. The passphrase is hashed client side with SHA-256 and only the hash reaches the server, so there is no identity check to talk your way past, and no way to recover a forgotten passphrase. Those are the same property, stated in both directions, and the README says so instead of promising recovery it cannot deliver.
